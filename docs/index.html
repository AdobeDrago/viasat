Viasat · Marketing Site Migration

Viasat on Edge Delivery Services

Rebuilding the viasat.com marketing site on Adobe Edge Delivery Services, authored in Document Authoring. So far that covers 5 pages (Home, Aviation, Energy, Satellite Internet and Enterprise), 4 of them merged to main and previewed, built from 7 custom blocks and 19 block variants, plus the production header, footer and section navigation. This is the handoff playbook: what was gathered, what was built, the decisions and assumptions behind it, and what's left.

Project overview

This effort recreates Viasat's public marketing site on Adobe Edge Delivery Services (EDS), authored through Document Authoring (DA). Each production page is rebuilt one at a time, on its own branch and pull request, and checked section by section against the live site with an automated parity gate (pixel and computed-style comparison at 1440 and 1280px). Existing blocks are reused wherever the content model fits, so later pages added options to shared blocks rather than new blocks.

Goals

  • Recreate the Viasat marketing experience on Edge Delivery Services, authored in DA.
  • Match the production pages closely enough to pass a measured parity gate, not just an eyeball check.
  • Model each production component (page heroes, promo bands, tile grids, carousels, news, FAQs) as an authorable block, and avoid duplication: one block with options instead of near-copies.
  • Keep the site navigable on EDS: links to pages that exist on EDS stay on EDS.

Approach

  • One page per branch and PR, always cut from the latest main: home-page, aviation, energy, satellite-internet, enterprise.
  • For each page: capture the source, map sections to blocks, agree the plan, build, gate against the source, run a full regression over every earlier page, lint, publish to DA and open the PR.
  • Section content is authored as EDS markup in import-work/pages/<page>/ and pushed to DA by script, so every page is reproducible.
  • Previewed at main--viasat--adobedrago.aem.page.

Navigation & links

Links copied from production pointed at https://www.viasat.com/…, so clicking around the EDS preview left the preview. The rule now is simple:

  • Built on EDS → relative link, e.g. /aviation/. Today: /, /aviation/, /energy/, /satellite-internet/, /enterprise/.
  • Not built yet → keeps its production URL, so it works instead of 404ing.

Relative links resolve on whatever host serves the page, so the same content works on main--…, any branch preview, .aem.live and the eventual production domain. The links live in the nav fragment, section-nav fragments, footer, home tiles and breadcrumbs; the header logo links to / in blocks/header/header.js.

When a new page is built, find every production link to it and make it relative: grep -rn "www.viasat.com/<page>/" import-work/pages blocks. Enterprise's two remaining links (nav and home tile) were fixed this way.

Header & section navs Done

The header is built from the /nav fragment: three sections become the primary row (industries), secondary row (with search) and sub bar (logo and links). The current section's primary link gets aria-current="page".

Parity gate & results

Every section is screenshotted on the source and the rebuild at the same width, then compared on pixels and on computed styles of matched elements. The pass bar is ≥ 99% pixel match and 0 style mismatches. Tuning stops after two iterations that don't reduce mismatches, and the residual is recorded rather than chased.

Decisions & assumptions

DecisionWhy
One page per branch and PREach PR is reviewable on its own branch preview, and the full regression catches anything a shared-block change breaks on earlier pages.
Options over new blocksAvoids near-duplicate blocks: promo grew to 11 options and tiles to 2, rather than five promo-like blocks.
Shared helpers in /scripts/Carousel controls (carousel.js), icon inlining (icons.js) and responsive images (optimize.js) are written once and imported by blocks, instead of repeated per block.
Section navs as fragmentsA section's sub-links are a small fragment named in page metadata, so the main nav exists once.
Images served from DALocal /media/ paths render broken (about:error) through the DA pipeline; the publish script uploads media to DA assets and rewrites paths to content.da.live.
Relative links only for built pagesKeeps the preview navigable without breaking links to pages that don't exist on EDS yet.
Stand-in heading fontUni Neue is licensed; headings use a fallback until it can be self-hosted.
Stand-in iconsSatellite Internet's icon grid and plan cards use Material Symbols SVGs in place of the source's proprietary icon font.
Native scroll carouselsCarousels use CSS scroll-snap with small controls instead of the source's Swiper library.
Stop rule for parityAfter two passes without fewer mismatches, the residual is recorded in the ledger and the page moves on.

Known limitations & accepted quirks Review

Accepted for this delivery. Each one is a candidate for follow-up before production.

  • Enterprise not previewed yet
    The page is built and pushed, but its content and media aren't in DA yet and there is no PR, so /enterprise/ returns 404 on the previews.
  • Content not published to live
    Everything is on .aem.page preview only; .aem.live still shows the boilerplate home page.
  • Enterprise residuals
    Industries grid, solutions and perspectives carousels and the light news band are 30–130px off the source height.
  • Heading font
    Uni Neue renders with a stand-in, so headings wrap and weigh slightly differently than production.
  • Desktop widths only
    The gate covers 1440 and 1280 (Satellite Internet 1440 only). Tablet and mobile layouts haven't been measured against the source.
  • Partial carousels
    The home news carousel has 4 of the source's 8 cards authored.
  • Search and unbuilt pages go to production
    The header search icon and links to pages not yet built still open viasat.com.
  • Videos are posters
    Video sections show the poster image without the source's player controls.

Next steps

  • Finish Enterprise: publish its content and media to DA, check the branch preview, open and merge the PR.
  • Close Enterprise residuals in the industries grid, carousels and news heights.
  • Self-host Uni Neue once licensing is confirmed.

Gotchas (hard-won)

  • Bare links get a <p> at runtime. EDS wraps loose cell content in a paragraph, which isn't visible in the authored HTML. Checking "is there a <p>?" false-positives; check for a second paragraph instead. This once added a phantom badge to every home tile.
  • Keep cell counts stable. news expects four cells (category, date, title, tags). Leave an empty category paragraph rather than deleting it.
  • Don't borrow a section class for one rule. It brings every other rule on that class with it (padding, heights). Write a small rule on the new section's own class.
  • Margin shorthand wipes earlier sides. Use margin-left / margin-right when you only mean the sides.
  • Regress every page after a shared change. Any edit to a block, styles.css or /scripts/ needs the gate re-run on all earlier pages, compared against their recorded counts.
  • Stylelint rejects several declarations on one line and descending specificity; npm run lint before every push.
